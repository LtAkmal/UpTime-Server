# Testing

## Go (agent, protocol, verifier)

```bash
make test        # go vet ./..., go test ./..., gofmt check
```

Without a local Go toolchain:

```bash
docker run --rm -v "$PWD":/src -w /src golang:1.27.1-bookworm make test
```

Covered:

- canonical encoding (sorting, strictness, every rejection case), schema validation;
- Ed25519 signatures: valid, wrong key, modified timestamp/sequence/status/prev,
  missing context prefix; deterministic signatures; stable fingerprints;
- hash chain: valid chain, modified payload, deleted middle event, changed previous /
  payload / event hash, reordering, wrong node, unknown key, key revoked before an event,
  receipt time outside the clock window, inflated uptime summary, duplicate sequence;
- range proofs with anchor and tail;
- uptime formula: silence, reboot, open outage, pre-monitoring gap, no data, clipping,
  merged reboot + silence;
- agent: key file 0600 / state directory 0700, loose permissions refused, one-time
  token, signed and chained boot/heartbeat/stop events, start vs. boot detection, lost
  reply recovery, refusal to follow a head it did not sign, bounded retry with backoff,
  no private key or token in logs or state files, configuration validation (plain HTTP
  needs an explicit opt-in, world-writable config refused), `/proc` readers.

`testdata/vectors/protocol-v1.json` is generated by `make vectors` and checked by both
the Go and the PHP tests, so the two implementations cannot drift apart.

## PHP (collector)

Run inside a Pterodactyl panel checkout with its test database configured:

```bash
/path/to/UpTime-Server/collector/laravel/install.sh /path/to/panel --register --with-tests
cd /path/to/panel && vendor/bin/phpunit tests/Integration/Uptime
```

Covered (41 tests): shared vectors in PHP; ingestion (valid, invalid signature, wrong
key, modified payload, unknown node/key, non-canonical bytes, revoked key, disabled node,
idempotent duplicate, replay, duplicate sequence, stale sequence, sequence gaps, clock
window, chain head mismatch, reboot downtime, monotonic/clock/build anomalies, body
limits); chain verification (valid, model and trigger refusal of updates/deletes,
modified payload, deleted event, changed hashes and columns, foreign key, public state
after failure, one notification); states and uptime windows, offline/online
notifications, outage rebuild; admin (access control, audit log, token hashing, one-time
use and expiry, rotation, manual key, revocation, no editable monitoring data, locked
parameters, administrator notes, public toggle, archiving); public page and API (no
login, no internal hostnames/addresses/tokens, transparency wording, source links,
proof recomputation, no-data and outage states).
